## 2. Technology and boundaries

- The app MUST use the existing React, TypeScript, Vite, and Tailwind CSS setup, with npm and the committed lockfile.
- Target Node.js 24, recorded in `.nvmrc` and `package.json` engines. Keep the Oxlint `jsx-a11y` plugin enabled; static accessibility linting supplements interaction checks.
- Tailwind MUST style page layout, typography, controls, and responsive behavior. Stimulus colors and geometry MUST be explicit typed constants or SVG attributes rather than inherited theme values.
- Use local React state for interaction. Each static page mounts only its own experience, without a router, global state, a component library or a backend.
- Static stimuli SHOULD use SVG. Canvas requires a documented performance or rendering need and an equivalent accessible description.
- The experience MUST run without runtime requests to research sites, image hosts, or other external services. Source links may navigate externally when selected.
- Do not add dependencies unless existing browser or project capabilities cannot reasonably meet the requirement.

## 4. Scientific and rendering integrity

- Identical targets MUST derive their fills and dimensions from shared values. Never simulate the effect by assigning different target colors.
- A reveal MUST modify only the context identified in the feature spec. Target positions, dimensions, fills, and background MUST remain invariant unless that feature explicitly defines a separate comparison mode.
- **Approved starburst inducer comparison (25 October 2026):** only [Scintillating starburst](scintillating-starburst.md) may compare its polygon pattern by removing the specified rotated heptagon pairs while preserving the same unrotated paths, strokes, surface and frame. There is no pair of equal-value targets and no ray shape is drawn. Name the operation precisely; do not claim all cues for perceived rays are absent from the image or promise perceptual disappearance. No opacity summation, filters, ray overlays or animation. This does not alter the approved scintillating-grid or Vanishing dots contracts.
- **Approved snakes pattern comparison (25 October 2026):** only [Rotating snakes](rotating-snakes.md) may intentionally change the two intermediate oval classes to the specified equal gray while keeping all existing sector/ellipse/ground nodes, geometry, fixed SVG orientations, black/white fills, surface and frame. The owner accepted the refined rounded-element construction after prototype review; its exact geometry/defaults live in the feature spec. State that colors/image statistics changed; it is not context removal, a same-value reveal, an equal-luminance control or an identical-pixel comparison. Both modes remain completely static, without timers or playback; no actual motion exception is proposed. Reversal/palette controls are explicit parameter changes, not proof invariants.
- **Approved Asahi context-gradient exception (25 October 2026):** only [Asahi glare](asahi-glare.md) may use its explicit opaque radial SVG color gradient inside the eight removable petal paths. Keep the white target and surface flat, exact, opaque and outside every shaded path; no gradients on target-containing groups, blend modes, filters, glow, exposure manipulation or animation. Hide petals removes only context. This grants no gradient use to Fraser, starburst, neon or snakes and does not relax any approved feature's rules. The owner approved this contract and the feature spec on25 October2026; it applies only when Asahi is implemented.
- **Approved rigid-comparison contract (23 October 2026):** only [Jastrow](jastrow.md) and [Shepard's tables](shepard-tables.md) comparisons may intentionally reposition their specified existing target paths. Preserve the same nodes, shared local shape data, fill/stroke/style, unit scale, opaque surface and frame. Allow only explicit proper rotation and/or translation (orthonormal rotation, determinant +1); no scale, skew, reflection, morph, replacement/copy targets, recoloring or fading. Timed motion remains prohibited except for the approved Shepard/Jastrow guided-motion amendment below. Remove only context expressly identified by the feature spec. Labels, descriptions and proof MUST say that the shape moved/rotated for comparison, rather than claiming unchanged positions or context-only revelation. Verify exact transformed-vertex/path coincidence and congruence, not just equal areas or bounding boxes. This contract applies only to these two approved features and does not alter any existing feature.
- **Approved guided-comparison motion amendment (24 October 2026):** only [Shepard section7](shepard-tables.md#7-approved-guided-comparison) and [Jastrow section3](jastrow.md#3-approved-guided-comparison-and-controls) may use explicit user-started, pausable/reversible3200ms guided motion and manual progress scrubbing. Preserve both original target nodes/local geometry/styles, unit scale, surface and frame, with exact endpoint transform strings. No third proof copy/guide, morph, recoloring, opacity effect, loop or page-load motion. Require immediate match/separate plus manual scrub under reduced motion, hidden/preference-change pause, no auto-resume, one bounded RAF only while explicitly playing and cleanup on pause/Back/Reset/unmount. Back preserves size/disclosure; Reset restores all defaults; size changes pause without losing progress. Announce stages/endpoints only. Share the controller and native transport only where used by these two features; each invocation owns independent state, each feature its geometry/easing. Other features remain static. The owner approves this extension before Jastrow implementation; Shepard’s calibrated construction is preserved.

## 8. Verification and completion

3. Meaningful tests verify target identity, geometry invariants, control boundaries, reveal preservation, and reset behavior. Avoid snapshot-only tests and assertions that merely repeat implementation constants.
4. In an available Chromium browser, inspect initial, revealed, adjusted, and reset states at 320 and 1440 CSS pixel viewport widths, plus 200% zoom. Verify keyboard access, focus, labels, disclosure behavior, and accessible names/states. Record browser version, displayed stimulus dimensions, parameters, and device pixel ratio.
5. Sources, attribution, instructions, and known limitations are present. Feature criteria assigned to implementation pass. Any required engineering check that cannot run MUST be reported as unverified; record the blocker without inventing a pass.

Automated accessible-name/state assertions, keyboard checks, and linting cover the agreed interface requirements.
